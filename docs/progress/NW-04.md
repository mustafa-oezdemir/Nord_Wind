# NW-04 — CI und gemeinsame Qualitätsschranken

- **Status:** Lokal geprüft; der erste GitHub-Actions-Lauf des Pull Requests steht noch aus.
- **Umsetzung:** [CI-Workflow](../../.github/workflows/ci.yml) mit einem sequenziellen Job `quality`; Angular ESLint und Prettier-Prüfung; Go-Format, `go vet`, Go-Tests, Angular-Tests/Typecheck/Build, `npm audit`, `govulncheck`, Compose-Syntax und Docker-Builds. `.gitattributes` fixiert LF für Quell- und Workflow-Dateien über Windows-/Linux-Checkouts hinweg. Die [PR-Anleitung](../verification/ci.md) nennt den erforderlichen Statuscheck.
- **Abhängigkeiten:** Der erste Go-Sicherheitsscan fand sieben erreichbare Schwachstellen in drei Modulen. `x/net`, `x/text` und `quic-go` wurden auf korrigierte Versionen aktualisiert. Der erneute Scan meldete null erreichbare Schwachstellen; drei weitere Meldungen betreffen nicht aufgerufene Funktionen in eingebundenen Modulen.
- **Lokale Prüfungen:** `npm ci`, Prettier, Angular-Lint, zwei Angular-Tests, Typecheck, Angular-Build und `npm audit --audit-level=high` bestanden. `go test ./...`, `go vet ./...`, `go mod verify` und `govulncheck@v1.9.0 ./...` bestanden. Beide Docker-Ziele bauten mit den aktualisierten Lockdateien. `actionlint` prüfte den Workflow ohne Fehler.
- **Token, Cache und Secrets:** Nur lesender Repository-Zugriff, kein gespeichertes Checkout-Token, keine Secrets im PR-Job, keine gemeinsamen Node-/Go-Caches, kein Image-Push. Die Compose-Prüfung verwendet nur einen Dummy-Wert.
- **Schutzregel:** Das private Repository liefert beim Lesen von `main`-Branch-Protection HTTP 403 mit dem Hinweis auf GitHub Pro oder ein öffentliches Repository. Ein verpflichtender Statuscheck konnte deshalb nicht gesetzt werden. Die rote Testprüfung kann einen fehlgeschlagenen Job zeigen, aber Merge-Blockierung ist aktuell nicht nachgewiesen.
- **Offen:** GitHub-Actions-Ergebnis des PRs abwarten und den dokumentierten Stand danach aktualisieren.
